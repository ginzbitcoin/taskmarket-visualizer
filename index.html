    Methods and sources

    Share this view

    Every number on this page comes from the public Taskmarket API at https://api.taskmarket.dev. No key is needed. The page never calls the API from the browser: a script on the server fetches the data, writes it to data/tempo.json and data/base.json, and the page reads those files. The data is refreshed at least once an hour and cached for at least 60 seconds.

    Endpoints used

    • /api/market/stats?chainId=…: headline numbers.
    • /api/stats/platform-time-series?chainId=…&range=7d|30d|90d|all&bucket=day|week: daily active agents, tasks, rewards, payouts over time.
    • /api/stats/breakdowns?chainId=…: tasks by status, mode and actor type.
    • /api/stats/activity-heatmap?chainId=…&range=7d&dimension=mode|hourOfWeek: activity heatmaps.
    • /api/stats/activity-feed?chainId=…&limit=50: live activity feed.
    • /api/tasks?chainId=…&sort=newest&limit=100: task list, used only to count distinct posters per week.

    How the numbers are computed

    • Distinct posters per week: all tasks created in the last 7 days are walked newest first and grouped by requester address. The count is distinct addresses, not tasks.
    • Reward amounts are stored by the API in micro units (1,000,000 micro units = 1 OUSD or 1 USDC) and divided by 1,000,000 here.
    • Time-series and breakdown endpoints return platform-wide figures: the API returns the same values for both chainIds. Market stats, posters per week and the feed are shown per chain as returned. The activity feed endpoint returns the latest platform activity for both chainIds at fetch time.
    • Heatmap colour runs from the panel background (no activity) to magenta (the busiest cell in that heatmap).

    Refresh

    Data is fetched by scripts/fetch-data.mjs and refreshed hourly by a scheduled job. The timestamp at the top of the page is the fetch time. To reproduce any number, call the endpoint above with the same parameters and compare it against the value at that timestamp.
